# نصب MikroTik CHR روی VPS از محیط Rescue

این پروژه ایمیج رسمی **MikroTik Cloud Hosted Router (CHR)** را روی دیسک یک ماشین مجازی x86_64 می‌نویسد. برای کاهش خطاهای mount و boot، نصب از **محیط Rescue لینوکس** انجام می‌شود؛ دیسک مقصد باید کاملاً unmount باشد. داده‌های دیسک انتخابی پاک می‌شوند.

> **هشدار:** پیش از اجرا از داده‌ها و تنظیمات نسخهٔ قبلی پشتیبان بگیرید، دسترسی کنسول پنل ارائه‌دهنده را بررسی کنید و نام دیسک را خودتان تأیید کنید. این اسکریپت برای نصب روی دیسک در حال استفادهٔ Ubuntu طراحی نشده است.

## تغییرات این نسخه

- دانلود ZIP ایمیج RAW فقط از `download.mikrotik.com` و باز کردن آن با `unzip`.
- انتخاب **صریح** دیسک؛ پذیرش `/dev/vda`، `/dev/sda` و `/dev/nvme0n1` بدون حدس زدن از خروجی `fdisk`.
- توقف نصب اگر دیسک یا هر پارتیشن آن mount باشد، دیسک خواندنی نباشد، ایمیج از دیسک بزرگ‌تر باشد، ZIP خراب باشد یا جدول پارتیشن معتبر نباشد.
- پاک‌سازی امضاهای قدیمی دیسک (از جمله GPT پشتیبان)، نوشتن با `dd`، سپس `sync` و مقایسهٔ بایت‌به‌بایت بخش نوشته‌شده با ایمیج.
- حذف mount کردن پارتیشن ایمیج و reboot اضطراری SysRq. راه‌اندازی مجدد از پنل سرور، پس از غیرفعال کردن Rescue، انجام می‌شود.
- پذیرش **هر شمارهٔ انتشار رسمی 6.x یا 7.x** با `--version`؛ در نتیجه نسخه‌های جدید بدون تغییر کد قابل نصب هستند، به شرطی که فایل RAW آن‌ها در مخزن رسمی منتشر شده باشد.

## نسخه‌ها

| نسخه | کانال در ۲۷ سپتامبر ۲۰۲۶ | وضعیت در اسکریپت |
| --- | --- | --- |
| `7.24.4` | Stable | پیشنهاد برای نصب تازه |
| `7.23.7` | Long-term | پیشنهاد برای کانال بلندمدت |
| `6.49.22` | Long-term | فقط برای نیازهای سازگاری قدیمی |

نسخه‌های قبلی اسکریپت (`7.14.3`، `7.9`، `7.7`، `6.49.15` و `6.49.13`) و هر نسخهٔ عددی رسمی دیگر نیز با `--version` قابل انتخاب‌اند. نسخه‌های development/beta عمداً در ورودی عمومی پذیرفته نمی‌شوند. برای بررسی نسخهٔ روز و انتخاب فایل مناسب، [صفحهٔ رسمی CHR](https://mikrotik.com/download/chr) را ببینید. وجود یک شمارهٔ نسخه به‌تنهایی به معنی موجود بودن فایل RAW آن نیست؛ دانلود نامعتبر پیش از هرگونه نوشتن روی دیسک متوقف می‌شود.

## پیش‌نیازها

- VPS یا VM با پردازندهٔ `x86_64` و دیسک مجازی قابل بوت؛ این روش روی کانتینر LXC/OpenVZ اجرا نمی‌شود.
- **Rescue Linux** بوت‌شده با **Legacy BIOS** و دسترسی root. اگر VM در UEFI بوت شده باشد، اسکریپت پیش از دانلود متوقف می‌شود؛ firmware را از پنل ارائه‌دهنده تغییر دهید یا از ایمیج سازگار با روش نصب آن ارائه‌دهنده استفاده کنید.
- دسترسی به کنسول/VNC پنل ارائه‌دهنده برای نخستین ورود و عیب‌یابی شبکه.
- `curl`، `unzip`، `util-linux` و `coreutils` در Rescue. روی Rescue مبتنی بر Debian/Ubuntu:

```bash
apt-get update
apt-get install -y curl unzip util-linux coreutils
```

فضای خالی محل کار (`/tmp` یا مسیر `--workdir`) باید برای ZIP و ایمیج استخراج‌شده کافی باشد. اگر `/tmp` روی RAM قرار دارد و فضای کافی ندارد، مسیری روی یک دیسک **غیر از دیسک مقصد** بدهید.

## نصب

1. از پنل ارائه‌دهنده Rescue را فعال کنید و با SSH یا کنسول وارد آن شوید.
2. با `lsblk -o NAME,SIZE,TYPE,MOUNTPOINTS,MODEL` نام **کل دیسک** مقصد را پیدا کنید. پارتیشن‌هایی مانند `/dev/vda1` مجاز نیستند.
3. اسکریپت را دریافت و پیش از اجرا بررسی کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/Digitalvps-Ir/Mikrotik-Ubuntu/main/script.sh -o script.sh
less script.sh
sudo bash script.sh --disk /dev/vda --version 7.24.4
```

در تأیید تعاملی باید دقیقاً عبارت نشان‌داده‌شده، مانند `ERASE /dev/vda`، را وارد کنید. برای اجرای از پیش تأییدشده می‌توان `--yes-erase` داد. اگر SHA-256 معتبرِ ZIP را از یک منبع قابل اعتماد دارید، آن را با `--sha256 HASH` بررسی کنید. اسکریپت مقدار checksum منتشرنشده‌ای را به‌جای سازنده حدس نمی‌زند.

```bash
sudo bash script.sh --disk /dev/nvme0n1 --version 7.23.7 --workdir /mnt/other-disk
```

4. پس از پیام **byte-for-byte verification succeeded**، Rescue را در پنل غیرفعال و VM را power cycle کنید.
5. از کنسول پنل وارد CHR شوید، برای کاربر `admin` رمز قوی تنظیم کنید، سپس شبکه و سرویس‌های مدیریتی را طبق نیاز خود تنظیم کنید.

اسکریپت IP، gateway، DNS، firewall یا رمز RouterOS را به ایمیج تزریق نمی‌کند. Ubuntu ممکن است IP ثابت داشته باشد، در حالی که CHR پس از بوت به تنظیمات متفاوتی نیاز پیدا کند. برای سرور بدون DHCP یا بدون کنسول قابل دسترس، **پیش از پاک کردن Ubuntu** روش تنظیم شبکه در CHR را با ارائه‌دهنده هماهنگ کنید. هیچ نتیجه‌ای دربارهٔ دسترسی SSH پس از reboot صرفاً از موفقیت `dd` قابل استنتاج نیست.

## عیب‌یابی

| پیام/علامت | علت محتمل و اقدام |
| --- | --- |
| `target disk ... mounted or in use` | Rescue را از یک محیط مستقل بوت کنید و پارتیشن‌های دیسک مقصد را unmount کنید. از اجرای نصب روی ریشهٔ Ubuntu فعال خودداری کنید. |
| `UEFI mode` | firmware ماشین مجازی با این روش RAW سازگار نیست؛ Legacy BIOS را در پنل انتخاب کنید یا روش نصب تصویری سازگار ارائه‌دهنده را به کار ببرید. |
| `ZIP failed its integrity check` یا `Unexpected ZIP contents` | دانلود ناقص یا فایل نامعتبر است؛ شبکه، شمارهٔ نسخه و لینک رسمی را بررسی کنید. |
| `RAW image is larger than the selected disk` | دیسک بزرگ‌تری انتخاب کنید. |
| خطای `dd` یا `cmp` | دیسک ممکن است ناقص نوشته شده باشد. از Rescue خارج نشوید؛ سلامت دیسک و فضای آن را بررسی و نصب را از ابتدا تکرار کنید. |
| CHR بوت شد اما شبکه ندارد | از کنسول ارائه‌دهنده IP، gateway و رابط شبکه را بررسی کنید. تنظیمات Ubuntu به‌صورت خودکار منتقل نمی‌شوند. |
| VM بوت نمی‌شود | Rescue را غیرفعال کنید، ترتیب بوت و firmware را در پنل کنترل کنید و نتیجهٔ کنسول را با پشتیبانی ارائه‌دهنده بررسی کنید. |

## محدودیت‌ها و منابع

این ابزار جایگزین Ubuntu با CHR می‌شود؛ ابزار ارتقای RouterOS موجود نیست. برای ارتقای CHR نصب‌شده، از روند به‌روزرسانی خود RouterOS و پشتیبان‌گیری استفاده کنید. لایسنس Free CHR محدودیت سرعت دارد؛ جزئیات را در [مستندات رسمی لایسنس](https://manual.mikrotik.com/docs/getting-started/routeros-licensing/chr/chr-licensing/) ببینید.
